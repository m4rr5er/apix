# 上下文交接

一次完整交接分四步，**必须按顺序做完**。任何一步没完成，就不要进入下一步。

## 何时使用

- 用户点击 APIX 的「压缩上下文」
- 用户说「准备压缩」「做一次交接」「整理一下再压缩」「这轮太长了换个会话继续」

## 铁律

1. **不要自己发起压缩。** 交接做完后只输出结束标记，APIX 会自动触发压缩。压缩是用户级操作，你无权发起，也不要在回复里模拟它。
2. **不要删用户的东西。** 「整理」是把散落文件归位，不是清理。任何删除、覆盖、重命名已有文件之前都要先说明并征得同意。
3. **把交接文档写给"失忆后的你自己"。** 压缩之后你不记得这轮对话的任何内容——只有这份文档能救你。写的时候假设读者对项目一无所知。
4. **宁可写多，不要写少。** 交接文档不受上下文限制（它写在磁盘上），所以细节不要省略。

## 第一步：整理工作区

目标是让下一轮打开目录时一眼看清项目结构。

1. 先看工作区顶层有什么，以及是否已有约定的目录结构。
2. 找出散落的文件：
   - 临时脚本：`*.py` `*.sh` `*.ps1` `*.js` `*.mjs` `*.ts` 散在根目录
   - 测试与探针：`test_*.py`、`*_probe.js`、一次性验证脚本
   - 输出产物：日志、导出的 json/csv、抓包结果、截图
   - 文档：散落的 `.md`、笔记
3. **已经有约定结构的**（比如 `scripts/`、`tests/`、`docs/`）→ 直接归位。
   **没有约定结构的** → 先提出一个最小建议结构给用户确认，不要擅自开新目录。
4. 移动优先于复制。遇到同名冲突**停下来报告**，不要覆盖。
5. 不要动：`.git`、`node_modules`、虚拟环境、构建产物目录、以及用户没提过的大目录。

整理完列一张表：`原路径 → 新路径`，让用户能一眼核对。没有需要归位的文件就直说，别硬凑。

## 第二步：写交接文档

写在 `<工作区>/note/handoff/` 下（目录不存在就创建；`note/` 是用户看得见的位置，
不要藏进 `.apix/` 这类点目录里）：

- 编号文件：`note/handoff/<N>-<YYYYMMDD-HHmm>.md`
  `N` = 该目录下已有文档数 + 1（没有就从 1 开始），这是**第几次压缩会话**。
- 同时把同样内容写到 `note/handoff/LATEST.md`，让路径保持稳定，下一轮不用去找编号。

按下面的模板写，**每一节都要有实质内容**。确实没有内容的节写「无」，不要整节删掉。

```markdown
# 上下文交接 · 第 <N> 次

- 时间：<YYYY-MM-DD HH:mm>
- 工作区：<绝对路径>
- 会话主题：<一句话>

## 之前做了什么

按时间顺序列已完成的事，每条写清楚「做了什么 → 结果是什么」。
不要写「优化了代码」这种空话，要写「把 X 从 A 改成了 B，因为 C」。

## 当前状态

现在项目处于什么状态？哪些能跑、哪些不能跑？最后一次验证是什么时候、结果如何？

## 还有什么目标

还没完成的目标，按优先级排。区分「必须做」和「最好做」。

## 暂定的后续计划

下一步具体打算怎么做。如果已经决定了实现方案，把方案写下来；
如果还在几个方案之间犹豫，把候选方案和各自的取舍写下来。

## 踩过的坑

每个坑写三件事：**现象 → 根因 → 下次怎么避免**。
这一节最重要，写的时候要具体到能复现的程度。

## 压缩后仍需记住的关键细节

那些一忘就要重新摸索半天的事实。例如：
- 关键的绝对路径（配置文件、数据、凭据位置）
- 特殊的环境约束（哪个命令必须用哪个 shell、哪个端口被占用）
- 用户明确表达过的偏好和禁区（不要动什么、必须用什么风格）
- 已经在用的第三方组件的接口约定
- 已知的外部依赖状态（哪个服务不可用、哪个 key 已失效）

## 未决问题

需要用户拍板但还没定的问题。
```

## 第三步：给用户首轮提示词

交接文档写完**并确认无误**后，输出一个代码块，内容是一句可以直接粘贴到新会话的话：

````
请仔细阅读 <LATEST.md 的绝对路径> 文档，然后继续 <下一步要做的事>
````

- 路径必须是**真实绝对路径**，不是相对路径、不是占位符。先确认文件确实存在。
- `<下一步要做的事>` 用一句话概括「暂定的后续计划」里的第一件事。
- 这个代码块要**单独成段**，前后不要混入其它内容，方便用户一键复制。

## 第四步：输出结束标记

最后一行单独输出：

```
[[APIX-HANDOFF-READY]]
```

这是给 APIX 的信号，它看到这行才会触发压缩。**只有前两步都真正完成了才能输出它。**

如果因为任何原因没能完成交接（缺权限、写不进去、需要用户先做决定），**不要输出这个标记**，
直接说明卡在哪里。APIX 不会压缩，你可以继续和用户商量。

## 反模式

| 别这么做 | 为什么 |
|---|---|
| 交接文档只写「已完成若干优化」 | 压缩后你完全不知道优化了什么，等于没写 |
| 直接输出结束标记，跳过整理和文档 | APIX 会压缩，但下一轮你会从零开始摸索 |
| 把大段代码贴进交接文档 | 代码在仓库里，文档里只写路径和「为什么这么写」 |
| 自作主张删除「看起来没用」的文件 | 那不是整理，是破坏 |
| 在交接文档里写「详见上文」 | 压缩后没有「上文」 |
